# 探针 · 回归 · 发布 操作手册

> 命令都在 `$SITE` 下执行。探针放在 `$PROBE`。
> 探针**只读**站点文件，不改任何东西 —— 它是独立复核，不是复用上一步的中间变量。

## 0. 验证分三层，缺一层就被另一种失败模式打穿

| 层 | 作用 | 形态 |
| --- | --- | --- |
| **探针** | 细粒度断言某个行为 / 结构 / 渲染 | 单文件脚本，退出码 0 = 绿 |
| **棘轮** | 防退化计数（文件数 / 体积 / 声明数 / 禁用词集合） | 计数 + 集合双断言 |
| **回归套件** | 一批探针串起来跑，判整体没坏 | 清单数组 + 跑批器 |

## 1. 三种探针形态

### 1.1 静态探针（不启浏览器）

直接读磁盘，秒级：

```js
const idx = read('$ENTRY');
ok(idx.charCodeAt(0) === 0xFEFF, 'BOM 在位置 0');
ok(idx.split('<script src="data.js"></script>').length === 2, '数据脚本被引用 1 次');
```

要点：

- 断言**只比形态**（BOM / 行尾 / 出现次数 / 关键字形态），**不写死会变的业务计数**；
- 数据层自洽性断言要**从数据层 eval 重算**，不采信数据层自己报的数；
- **注释开合用「深度口径」**（depth 从不许 < 0，末态 depth == 0），不用增量口径 ——
  增量口径的前提是基线本身配平，一旦基线有历史孤儿闭合就永远红；
- 对 HTML 注释里的历史引用要**判在元素上**（查某个元素里有没有旧名），不要全文扫；
- **必须从磁盘重新读**，不复用上一步的中间变量。

### 1.2 浏览器双协议探针

自带一个只读静态服务器，**同一套断言跑 `http://` 与 `file://` 两遍**：

```js
const srv = http.createServer((rq, rs) => { /* 读 $SITE 下的文件 */ });
await new Promise(r => srv.listen(8801, '127.0.0.1', r));
const b = await chromium.launch();
for (const proto of ['http://', 'file://']) {
    const c = await b.newContext({ viewport: { width: 1600, height: 1000 } });
    const p = await c.newPage();
    p.on('pageerror', e => errs.push(String(e)));   // 收集 JS 错误
    ...
}
```

要点：

- **双协议必须都跑** —— `file://` 下 CSSOM 是 opaque、`fetch()` 被 CORS 挡、ES Module 不可用。
  很多在 http 下能过的写法，在 file 下直接白屏；
- **等状态而不是固定 sleep**：`await p.waitForFunction(() => !document.getElementById('m').classList.contains('active'), null, { timeout: 15000 })`；
  固定 `sleep(1200)` 在负载下会假红；
- **不许吞异常**；
- **测量前先确认元素有非零宽度**；零宽优先判为**探针问题**；
- **存在性 ≠ 可见性**：元素在 DOM 里不等于它没被 `clip-path` 裁掉 —— 量几何；
- 截图存档，命名带协议（`http-card.png` / `file-card.png`）；
- 未捕获异常用**独立的退出码**（如 2）区别于断言红（1）—— 「脚本崩了」和「断言红」是两件事。

### 1.3 负向对照探针

喂**故意做坏的样本**，断言**必须报红**。

做法：在运行中的页面 DOM 里注入破坏（擦掉标题图标 SVG / 改 `preserveAspectRatio` 为 `none` /
把全部 `<text>` 清空），再跑同一套判据。

守卫不双向测，就不知道它是漏报还是误报 —— **两者同等致命**。

## 2. 棘轮

防退化的**计数 + 集合**双重断言：计数类（某类声明条数、文件数、体积）、集合类（禁用词表等）。

- **白名单从原始备份自动推导，不手写** —— 手写白名单漏两条就会持续 FAIL；
- **判据按语境收窄，不按字面** —— 过宽的守卫第一天就红，然后被人随手删掉，等于没有守卫；
- 守卫**不得写死数据文件名** —— 改名后会悄悄失效；找不到文件时**报错而非跳过**；
- 棘轮基线是**快照**，不追移动目标：并发在途时计数自己会变，此时停止同步基线，收工后一次性校准；
- **用户拍板的锁**（例如「某个数值必须清零」）**不是基线**，抬它要用户点头；
- 「计数从 36 掉到 26 却仍报 0 FAIL」说明守卫被无关文件杀死了 —— 这比没有守卫更危险。

## 3. 全量回归跑批

**两个跑批器常常并存，行为不同，别混用**：

| 跑批器 | 特点 |
| --- | --- |
| 清单式（stdout） | **套件清单的源**（`SUITES = [[名字, 说明], ...]`）；带**失败自动重跑一次**与抖动判定 |
| 带日志式 | **每套跑完立刻 `appendFileSync` 落盘**（Node 缓冲到 64 KB，进程被 TerminateProcess 时日志会是空的）；**支持续跑**（日志里已有 DONE 的跳过）；**通常不含抖动重跑** |

要点：

- **必须串行** —— 多套浏览器同开会互抢 CPU，计时失真且偶发假红；
- **每套结束立刻 append 一行到日志**（不是进程退出才落盘）；
- **失败自动重跑一次**，重跑仍红才算真失败；
- **抖动与真回归要分开报**：
  - 每轮红的套件不同 + 复跑绿 = **抖动**；
  - 红的套件相同 + 复跑仍红 = **真回归**；
- **抖动的常见根因**：探针普遍断言「零 console 报错」，而页面要拉外部字体 / CDN
  ⇒ 外网一抖就整条断言红。判据是**双协议一红一绿**（同一次运行里 http 红、file 绿）；
- **保留首跑失败行** —— 重跑结果覆盖首跑后，「首跑为什么红」就彻底丢了，没法追因；
- **套件数变更要同步改掉写死的套件数断言**（跑批器里常有 `if (NAMES.length !== 67) exit(1)`）。

### 判红的两个坑

```js
/* ⚠ 两处都踩过：
   ① 必须先 split('\n') 再筛 —— `out.match(/^FAIL/gm)` 返回的是**匹配串**(全是 "FAIL"),
      不是行, 对它做行级过滤根本不生效, 于是「FAIL = 0」这条汇总行被算成 1 条 FAIL。
   ② 还要排除「FAIL = 0」这类**汇总行**本身, 否则全绿的套件也会显示有失败。 */
const lines = out.split('\n');
const nFailLines = lines.filter(l => /^FAIL/.test(l) && !/^FAIL\s*[=:]\s*\d/.test(l)).length;
```

⇒ **判红 = `exit != 0` OR 存在不以 `FAIL = <数字>` 开头的 FAIL 行。**

### 加一套新探针

1. 写 `$PROBE/<序号><字母>_<主题>.js`，退出码 0 = 绿；
2. 在运行清单的 `SUITES` 数组里加一行 `['<名字>', '<一句话说明>']`；
3. **同步改跑批器里写死的套件数断言**；
4. 若探针改动了站点文件，记得在文档同步里记一行。

## 4. 本地静态服务器

```powershell
$p = Start-Process -FilePath 'python' -ArgumentList "$SITE\_serve.py","8000" `
     -WorkingDirectory $SITE -WindowStyle Hidden -PassThru
Start-Sleep -Seconds 4
Get-NetTCPConnection -LocalPort 8000 -State Listen    # 确认端口归属 PID
```

⚠ **不要挂在工具的后台任务里** —— 后台任务通常有运行时长上限（常见 1 小时），
到点进程被回收、服务随之消失。用独立进程才跨上限存活。

## 5. 发布前：查泄露面

零构建站的核心风险是 **「工作目录 = 部署根目录」** —— 根目录下的一切都会被传上去。

```powershell
node "<skill>\scripts\deploy-audit.js" $SITE
```

它扫三类东西：**该排除但还在根目录的文件**（内部文档 / 日志 / 备份 / 配置）、
**源码与注释里的本机绝对路径**、**明文邮箱**。

排除清单的规则：

- 清单本身也要被排除（否则它泄露内部结构）；
- 备份文件（`*.bak` / `*.orig` / `*~`）一律排除；
- 工具脚本目录（`$PROBE`）排除；
- **有意对外下发的二进制**（示例 PDF / 大图）要**显式写进白名单**，否则会被人当垃圾排除掉。

## 6. 发布与线上核对

| 环节 | 做法 | 注意 |
| --- | --- | --- |
| 上传 | 控制台 / 工具 | **只传入口 HTML 是不够的** —— CSS/JS 没传上去，线上跑的就是旧版 |
| 一致性核对 | 部署一致性检查器 | 级联对照**必须走 http**；`file://` 下 CSSOM opaque，两边都空等于没查 |
| 二进制比对 | 读 buffer 比 hash | 文本管道把 UTF-8 当 Latin-1 解，差分结论全是假的 |
| CDN 刷新 | API 或控制台 | 先查配额（URL 刷新 / 目录刷新 / 预热各自的日限额与单次上限）；控制台的目录刷新默认是**标记刷新**，确定性清理要 API 加强制参数 |
| 去索引 | 搜索引擎的移除请求 | **`robots.txt` 是建议不是权限**，不能让已索引的页面消失 |
| 版本号策略 | 引用处**全改** | `href` / `src` / CSS `url()` / JS 拼的 URL，一处漏了就是一半新一半旧 |
| 凭据 | 只从环境变量读 | 不落盘、不进日志；一键脚本应支持 `--dry-run` |
